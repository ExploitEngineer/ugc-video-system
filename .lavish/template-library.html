Adverra Studio · Template pipeline

A template library — upload once, reuse forever

Right now every template run makes the user upload the AE file again, and each upload registers a brand-new duplicate in Nexrender. This plan persists uploaded templates and lets the user pick a saved one — no re-upload, no duplicate registration.

01

The problem today

What happens now

POST /templates/register registers the file with Nexrender, uploads the bytes, returns a nexrenderTemplateId — and saves nothing on our side. The id only survives inside that one run's runs.template snapshot.

no persistence no reuse path Nexrender fills with dupes

Why it hurts

  • Re-upload friction — the same 20–200 MB file goes up the wire for every ad that uses it.
  • Duplicate Nexrender templates — each upload is a fresh registration; the account accumulates identical copies (and, on paid plans, storage/clutter).
  • Re-introspection — we poll Nexrender to read the composition/slots again even though we already know them.
  • No "my templates" surface — the old catalog was removed; there is nothing to pick from.

How it works

Persist every registered template in a new templates table, dedupe re-uploads by content hash, and serve the library from GET /templates.

04

New templates table

One row per registered template (Drizzle, apps/api/src/db/schema.ts, one additive migration). Global for now — see the auth note in risks.

columntypepurpose
iduuid pkour stable id — the frontend + runs.template reference this.
nexrender_template_idtextthe Nexrender id from register — reused on every run, never re-created.
content_hashtext (indexed)sha256 of the uploaded bytes — the dedupe key that stops duplicate registrations.
display_nametextthe filename (optionally user-renamable later).
structurejsonbintrospected snapshot — slots, mainComposition, dims, suggestedAspectRatio. Skips re-introspection on reuse.
statustextprocessing → ready once Nexrender finishes introspecting.
created_at / last_used_attimestamptzsort newest / most-recently-used in the picker.
05

API changes

routechangebehavior
GET /templatesNEWList saved templates (id, name, slot counts, aspect ratio, status, previewless). Powers the picker grid.
POST /templates/registerCHANGEDHash the bytes first → if the hash exists, return the existing row (skip Nexrender entirely). Else register + upload + insert a row.
GET /templates/:id/structureCHANGEDSame polling; also persist the structure snapshot onto the row once ready (so reuse never re-introspects). Keyed by our id now, not the raw Nexrender id.
DELETE /templates/:idNEW*Remove a template from the library (see decision 2). *Only if you want manage/delete.
POST /runstinyAlready takes templateId; it now resolves our templates.id → the stored structure + nexrenderTemplateId instead of re-fetching from Nexrender.

Web: template-upload-view.tsx gets the two-tab picker; lib/api.ts gets fetchTemplates() back (list) + reused-id plumbing. The brief page already accepts a templateId.

06

Before → after

today Re-upload every time

  • Upload the file again for each ad.
  • Every upload → a new Nexrender registration.
  • Re-introspect the same composition.
  • Nothing to pick from; no memory of past templates.

after Pick from the library

  • Upload once; every later run picks the saved template.
  • Re-uploading the same file is deduped by hash → zero new Nexrender registrations.
  • Structure snapshot reused — no re-introspection.
  • A "Your templates" grid on the start screen.
07

Decisions to confirm

Pick an option in each — selections queue as feedback; hit Send to Agent in the Lavish bar when done.

1 · Dedupe re-uploads by content hash?

If the user (or a teammate) uploads the exact same file again, should we detect it and reuse the existing Nexrender registration?

2 · Let users delete templates from the library?

A DELETE /templates/:id + a trash affordance on each card.

3 · Library scope — global for now?

Auth (F8) isn't built, so there are no users to scope to.
08

Risks & open questions

!
No auth yet (F8). A shared global library is the only option now; when auth lands, existing rows need an owner backfill / per-user scoping. Flagged, not blocking.
!
Nexrender-side lifetime. If Nexrender expires or garbage-collects an uploaded template, a saved row's nexrenderTemplateId could go stale. Mitigation: on a render "template not found", fall back to re-register from a stored copy — but we deliberately don't keep the .aep on Supabase, so a stale id would need a re-upload. Worth confirming Nexrender's retention.
?
Previews. Nexrender templates have no thumbnail. v1 shows name + slot counts + aspect ratio (as mocked). A real preview would need a render or a user-supplied image — out of scope unless you want it.
?
Hash vs "same template, tweaked". Content-hash treats a re-exported/edited .aep as a new template (different bytes). That's correct behavior, just noting it won't dedupe visually-identical-but-re-saved files.
